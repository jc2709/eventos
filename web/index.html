GUÍA DE PRÁCTICA

Comprueba lo que aprendiste

1. Publicación y consumo

Crea un pedido en modo paso a paso. Antes de procesar, el stock sigue igual: publicar un hecho no significa que todos lo hayan consumido. Procesa una entrega y observa Inventario.

2. Correlación de eventos

Reserva inventario y simula el pago. Envíos solo inicia cuando consume InventarioReservado y PagoCompletado con el mismo correlation_id. Comprueba que no se mezclan dos pedidos.

3. Fallos y recuperación

Activa el fallo, crea un pedido y procesa entregas. Notificaciones fallará, pero Inventario podrá reservar. Desactiva el fallo y reintenta la cola de fallos. Una entrega completada no vuelve a ejecutarse.

4. Persistencia

Cierra el servidor con Ctrl+C y vuelve a iniciarlo. SQLite conserva eventos, pedidos y entregas pendientes. Este historial permite auditar; la aplicación no reconstruye todo el estado mediante event sourcing.

¿Qué simplifica este laboratorio?

Todos los módulos viven en un proceso Python. El broker es una implementación educativa con SQLite; no es Kafka ni RabbitMQ. El modo automático ejecuta una entrega cada 0,6 segundos. No incluye pagos reales, correo, múltiples servidores ni CEP completo.
